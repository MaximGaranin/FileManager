# fm — терминальный файловый менеджер на ncurses

Двухпанельный файловый менеджер для терминала с вкладками, встроенным
интерактивным терминалом (libtsm), интеграцией с `nvim` и отдельным
окном для просмотра и управления процессами.

## Возможности

- Двухпанельный интерфейс: список файлов слева, превью справа.
- Превью текстовых файлов постранично, содержимого директорий, размеров
  бинарных файлов.
- Вкладки (до 9), переключение по цифрам `1-9`, `Tab` — быстрый прыжок
  на предыдущую активную вкладку.
- Встроенный терминал на базе `libtsm` и `forkpty`, переключение фокуса
  между панелью и терминалом по `Shift+Tab`.
- Открытие файлов в `nvim` прямо из встроенного терминала благодаря
  враппер-скрипту `~/bin/nvim`, который сигналом `SIGUSR1` просит `fm`
  открыть редактор на весь экран, а не внутри PTY.
- Копирование, перемещение, переименование, удаление файлов и папок
  (рекурсивно).
- Поиск по имени файла в реальном времени (`/`).
- Отдельное окно со списком процессов, отсортированным по времени
  запуска (новые сверху), с возможностью убить процесс через `Enter`
  (`SIGKILL`) или отправить произвольный сигнал через `s`.
- Корректная реакция на изменение размера терминала (`SIGWINCH`) —
  все панели, терминал и окно процессов пересчитывают геометрию.

## Горячие клавиши

### Файловая панель

| Клавиша         | Действие                                  |
|-----------------|--------------------------------------------|
| `j` / `↓`       | Курсор вниз                                |
| `k` / `↑`       | Курсор вверх                               |
| `l` / `→`       | Войти в директорию / открыть превью файла |
| `h` / `←` / `Backspace` | Выйти в родительскую директорию   |
| `Enter`         | Войти в директорию                        |
| `a`             | Создать файл                              |
| `A`             | Создать директорию                        |
| `y`             | Скопировать (yank)                        |
| `m`             | Переместить (yank для move)               |
| `p`             | Вставить скопированное/перемещённое       |
| `r`             | Переименовать                             |
| `d`             | Удалить (с подтверждением)                |
| `/`             | Поиск по имени                            |
| `t`             | Новая вкладка                             |
| `x`             | Закрыть текущую вкладку                   |
| `1`-`9`         | Переключение на вкладку по номеру         |
| `Tab`           | Переключение на предыдущую активную вкладку |
| `Shift+Tab`     | Переключить фокус панель ↔ терминал       |
| `P`             | Открыть окно процессов                    |
| `q`             | Выход из fm                                |

### Превью

| Клавиша    | Действие                     |
|------------|-------------------------------|
| `j` / `k`  | Скроллинг текста вверх/вниз  |
| `h`        | Вернуться к файловой панели  |
| `Enter`    | Открыть текстовый файл в nvim |

### Терминал

Весь ввод, кроме `Shift+Tab`, передаётся напрямую в шелл внутри PTY.
Открытие `nvim` из этого терминала автоматически переключает на
полноэкранный режим редактора через враппер и сигнал `SIGUSR1`.

### Окно процессов (`P`)

| Клавиша       | Действие                                  |
|---------------|---------------------------------------------|
| `j` / `↓`     | Курсор вниз по списку                      |
| `k` / `↑`     | Курсор вверх по списку                     |
| `PgDn`/`PgUp` | Быстрый скроллинг                          |
| `Enter`       | Убить выбранный процесс (`SIGKILL`)        |
| `s`           | Отправить произвольный сигнал по номеру    |
| `t`           | Закрыть окно и создать новую вкладку       |
| `P`           | Закрыть окно процессов                     |
| `q`           | Выход из fm                                |

Список процессов сортируется по полю `starttime` из `/proc/[pid]/stat`
(поле 22), поэтому самые недавно запущенные процессы отображаются
сверху, а старые — снизу.

## Зависимости

Для сборки нужны заголовки и библиотеки `ncursesw`, `libtsm`, `pthread`
и `libutil` (для `forkpty`). `pthread` и `libutil` входят в состав
`glibc`/`build-essential` и отдельно устанавливать их не нужно.

### Debian / Ubuntu

```bash
sudo apt install build-essential libncursesw5-dev libtsm-dev
```

### Fedora / RHEL / CentOS

```bash
sudo dnf install gcc ncurses-devel
```

Готового пакета `libtsm-devel` в стандартных репозиториях обычно нет —
собери `libtsm` из исходников (см. ниже).

### Arch Linux / Manjaro

```bash
sudo pacman -S base-devel ncurses libtsm
```

### Сборка libtsm из исходников (если нет готового пакета)

```bash
git clone https://github.com/Aracthor/libtsm.git
cd libtsm
meson setup build
ninja -C build
sudo ninja -C build install
sudo ldconfig
```

### Проверка перед компиляцией

```bash
pkg-config --cflags --libs libtsm
pkg-config --cflags --libs ncursesw
```

Если `pkg-config` не находит `ncursesw`, убедись, что установлен именно
wide-character дев-пакет (на Debian — `libncursesw5-dev`, отдельно от
обычного `libncurses-dev`), иначе не будет поддержки UTF-8.

### Опционально

- `nvim` — для открытия файлов из превью и встроенного терминала.

## Сборка

```bash
gcc -Wall -O2 fm.c -o fm \
  -I/usr/local/include \
  -L/usr/local/lib64 \
  -ltsm -lncursesw -lpthread -lutil \
  -Wl,-rpath,/usr/local/lib64
```

Флаги `-I/usr/local/include`, `-L/usr/local/lib64` и
`-Wl,-rpath,/usr/local/lib64` нужны только если `libtsm` установлена
вручную из исходников в `/usr/local`. Если `libtsm` установлена через
системный пакетный менеджер (Arch, либо собранная в стандартный путь),
эти флаги можно убрать:

```bash
gcc -Wall -O2 fm.c -o fm -ltsm -lncursesw -lpthread -lutil
```

## Запуск

```bash
./fm
```

Программа стартует в домашней директории пользователя и создаёт
временный враппер `~/bin/nvim`, который автоматически удаляется при
выходе из `fm`.

## Известные ограничения

- Отправка сигналов процессам других пользователей требует
  соответствующих прав (обычно `root`); при отсутствии прав `kill()`
  завершается с ошибкой `EPERM`, которая на данный момент не выводится
  в интерфейсе явным образом.
- Максимум 9 вкладок и 8192 элементов на директорию, 4096 процессов на
  снимок — ограничения заданы константами `MAX_TABS`, `MAX_ENTRIES`,
  `MAX_PROCS` и могут быть увеличены при необходимости.
